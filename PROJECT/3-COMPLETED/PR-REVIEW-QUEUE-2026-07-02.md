## Flow — preflight first, then review (per lane)

A PR-review lane's "preflight" is the light prep form (not `swarm-preflight`, which is a build-lane
readiness gate): **resolve the PR diff → seed it read-only → scaffold the relay thread → confirm the
harness is green.** Only then does the review turn run against that seeded artifact.

1. **Preflight (prep):** `gh pr diff <n> > <diff>`; `relay-automation/new-relay.sh --title "review PR #<n>" --reviewer <agent> --artifact-file <diff> --embed` (seeds the diff into the thread, fence-safe). Confirm `bash validate.sh` green + the reviewer CLI is on PATH.
2. **Review:** `relay-automation/relay-drive.sh --review-once --relay-file <thread> --artifact-file <diff> --agent-cmd relay-automation/<agent>-turn.sh` with `ALLOW_PATHS=""` (reviewer reports, never edits). Exit `0` = Approved, `5` = changes-requested (a *successful* single review), `3` = stall.
