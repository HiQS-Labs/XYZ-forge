## The one safety rule

Two lanes are safe to run concurrently **iff their write-sets are disjoint**. The
collision-free claim/heartbeat machinery (`tick`, `swarm-preflight`, `ALLOW_PATHS`,
worktree isolation) enforces this *mechanically* — but only if we hand it
non-overlapping path scopes. So the whole plan reduces to one fact:

> **`relay-automation/relay-turn-lib.sh` (26.7K) is the containment kernel.**
> Every lane that edits it is mutually exclusive with every other lane that edits it.
> It is the serialization bottleneck. Everything else can fan out.

Shim lanes are parallel-safe **with each other** because each shim is its own file —
but any shim lane that needs a *new kernel API* must wait for the kernel lane that
adds it (a dependency edge, not a collision).

## How to fire a lane

Per lane, the existing pipeline applies — no new control plane:

```
utils/swarm-preflight.sh --project-doc <PROJECT/**/doc.md>   # or --issues "#29"
   → ready packet (candidate/freshness/fix-still-required + lane assignment)
relay-automation/marathon-drive.sh ...   # build→gate→review, contained
```

- **Lane scoping:** give each lane an `ALLOW_PATHS` matching only its zone above; that
  is what makes "safe to parallel" true rather than hoped-for.
- **Lane assignment:** kernel → Codex builder + agy reviewer (or Opus inline);
  shims/independent → Sonnet High. Personal-data targets → agy reviewer-first.
- **Never** run two kernel lanes at once, even in separate worktrees — see the memory
  on commit-bypass orphaning a peer commit.
