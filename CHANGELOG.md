### Part B Phase 1 (R1 + G3) — monotonic epoch fencing: the stale-writer kernel fence
Closes the keystone gap in the adversarial-hardening track: turn ownership-by-convention into a kernel a buyer can trust unattended. A revived/zombie writer — **even with the same agent id** — can no longer advance, corrupt, or retire a task it no longer owns. (Kernel diff written on Opus per the ROADMAP model-assignment call; the surrounding test/docs are mechanical.)
- **Schema 0.1.0 → 0.2.0 (`src/events.js`):** additive optional `epoch` field on claim/mutation events. Absent ⇒ epoch 0, so pre-0.2.0 logs project byte-identically; non-epoch events stay byte-stable.
- **Kernel fence (`src/project.js` `fold` → `foldWithMeta`):** the current owner is the live claim with the **highest epoch**; a mutating event (`done`/`circuit_break`/`scope_changed`/`released`) is honoured **only** from that owner at `epoch >= owner.epoch`, else rejected and never applied. Two load-bearing sub-invariants: (1) a `released` retires a claim only if `release.epoch >= claim.epoch` — without it a replayed lower-epoch release would retire the current same-id claim (the keystone failure); (2) a handoff (`release --to`) is honoured only from the latest epoch, so a displaced writer can't redirect the reservation.
- **Epoch assignment (`src/claim.js`, `src/take.js`):** `task.claimed` carries `epoch = max(prior epochs for task) + 1`, computed under the existing `withClaimLock` (first claim ⇒ 1; a reclaim after reap strictly exceeds the displaced owner). Mutations stamp the owner's epoch (`src/scope.js`); `reap` stamps the reaped claim's epoch on its release.
- **Audit log (`.tick/rejected.jsonl` + `tick fences`):** every fenced event recorded as one JSON object/line (ts, task, type, fenced_agent/epoch, owner_agent/epoch, reason: `non-owner-agent` | `stale-epoch` | `stale-epoch-inert`). Rewritten in full each projection → a deterministic mirror of the event set (seed for R4/SIEM). Only post-takeover violations are logged; legitimate prior-epoch history (the reap release, old-owner scope) is silently superseded, not flagged. `tick log` gains `--epoch` (the replay vector for the chaos test).
- **`test/chaos-stale-writer.sh` (G3) — 13/13:** SCENARIO 1 is the keystone — alice claims (e1) → reaped → alice **re-claims (e2, same id)** → her buffered e1 done/scope/release replay *after* she re-owns; ownership passes (same id), only the epoch fences them; state byte-identical, owner still completes, verdict deterministic across re-projections. SCENARIO 2 covers cross-agent takeover (`non-owner-agent`). `validate.sh` **29/29**, zero regressions.
