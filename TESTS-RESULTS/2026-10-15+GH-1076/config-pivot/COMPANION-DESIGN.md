## Concrete strict contract for parent review judgment

A possible `wave-premerge-carrier@1` record would use a nested typed outcome, not a root generic PASS. It would bind `source_commit` (full OID and ancestry), `source_tree` (actual Git tree OID), actual base identity, producer owner and source revision, and an exhaustive list of original validation streams with blob IDs and SHA256. The only new carrier paths would be one schema-validated provenance record and its explicitly referenced original validation stream(s), all newly added regular files at fixed source/PR-bound names. The manifest itself is validated as a record; it must not claim a cyclic self-hash. An independently verified witness, when required, must bind the actual record/artifact bytes rather than a self-declared producer field.

The canonical reader would read immutable Git blobs, verify the exact source→carrier file set, reparse every stream using the canonical sequential validator and compare source identity, suite registry/revision, counters, omissions and envelope. It would return a verified companion set, not just a bool. The raw landing classifier may exclude only that returned set; all other original raw status/mode/path constraints remain. A new source edit, changed companion, unknown record/file or extra functional path fails to full. No receipt is reused as software qualification of a different tree.

The producer should be an explicit premerge mode of the existing wave qualification owner, reusing its disposable clone, bounded runner, real process identity, canonical telemetry validation and journal. It cannot simply call the current MERGED-only producer with fabricated metadata. Whether it may produce self-reported local evidence or needs a trusted CI witness is the outstanding trust decision. The former retains current repository local-proof limits; the latter needs a producer not currently present.

This changes a public proof contract, so propose one bounded plan review and one bounded final review of this extension (source/tree/producer/integrity/negative controls/rollout) for the parent's procedural decision. These are new allowances if granted, never resets of original plan/final or supplemental finalFAIL1/1. No consultant/fixture result substitutes for that decision. Existing @1 and @2 replay must retain historical behavior; version the expanded profile contract and preserve old readers rather than silently broadening old receipt authority. Missing or incompatible proof remains full; true test failure/identity drift stays fatal; main remains exact-main full macOS.

Controlled observations, not new registered CI cases, should cover: a real producer-backed ordinary premerge source→carrier→landing flow; tampered stream/digest; stale source/tree; wrong producer or witness; unsupported schema; unexpected third file; symlink/mode/rename; mixed runtime edit; failure/missing envelope; and rollback/old-version replay. Fully resealed false producer evidence must be explicitly distinguished from ordinary tampering: the existing self-report model cannot independently authenticate it.
