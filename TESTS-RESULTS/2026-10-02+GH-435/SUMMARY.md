## Passing controls and rejected hypotheses

Discovery's final original matrix contains 25 unique cases: 22 expected-behavior/refusal passes, 2 unset-HOME failures, and 1 deliberate wrong-root red control. It covers foreign/space/Unicode paths, symlinked locators and vendored roots, explicit override precedence, detached worktree, XDG configuration and shell-escaped environment output. Additional peer controls confirm F3; they are recorded separately rather than inflating that count. The existing runner envelope also correctly refuses missing and unwritable TMPDIR; a real EACCES write probe validates the permission fixture, and the writable control succeeds and cleans up. The existing Git sandbox guard also refuses read-only config and denied config.lock creation before any branch/index/sentinel change; restoring permissions permits the branch-switch control.

The installer matrix has 14 accepted unique case/mode combinations (10 v4 observe, 3 v5 full, 1 v7 no-Node observe), with 30 stdout/stderr streams including the repeated installation. The v4 zero-byte case used an incorrect initialization expectation; its 2 additional raw streams establish observed behavior but are excluded from accepted totals. The v6 missing-mode setup error produced 18 command-error rows, all excluded. Absent DB initializes; valid empty (#904) and populated ledgers preserve bytes; denied optional-skill writes warn while core installation succeeds; repeated install keeps runtime hashes and one registry entry; missing required Releases CLI/sqlite3 refuses before core copying. The Node-free deterministic installer/observe path succeeds through its fallback; the opt-in model-assisted doc-ready path was not exercised, so this does not invalidate Node as a prerequisite for all capabilities. Existing zero-byte/corrupt/wrong-schema/unreadable DBs remain intact. Observe mode explicitly reports their error and returns 0; full-mode controls for zero-byte, corrupt and unreadable files fail verification (wrong-schema full mode was not run). The initial “observe0 means false success” hypothesis was rejected against the mode contract and strict-mode controls. Do not overwrite an existing ledger or change observe semantics based on this campaign.

Existing focused checks: GH-478 43/43, adaptive ATE 15/15, GH-290 37/37 top-level assertions. GH-290 separately exercises 162 hostile variations (115 loaders + 18 landing mismatches + 29 receipt-writer variants), plus 2 valid controls; do not add assertion counts to variation counts. The current pairwise specimen produces 6 valid cases with 100% valid-pair coverage; the old three-argument API promptly raises TypeError. This does not reproduce the historical unmerged #478 hang. The real ATE timeout emits a failed timeout row and removes the TERM-resistant child.

A child surviving normal successful leader exit is a documented timeout-only contract boundary, not a confirmed bug. A stronger no-descendants-on-success promise needs an explicit decision and caller audit. Very short 60 ms initialization exhausted the ATE budget without running a case; that attempt was detected and excluded. Initial external probe import/fixture errors are retained but excluded from product findings. ATE internal timestamps are local wall time mislabeled UTC (F9); the outer wrapper captured actual UTC start/end times and remains the timing authority.
