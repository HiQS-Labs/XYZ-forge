The "consult" skill is a high-quality addition that introduces a necessary architectural primitive: the **parallel 1:N advisory loop**. It is technically superior to a "best-effort revert" because it uses **provable isolation via throwaway worktrees**.

### 1. Concept Soundness
**[Pass]** The distinction between `consult` (parallel, 1-shot, advisory) and `relay` (iterative, N-round, generative) is sharp and well-defined. A paying user will understand that a "consult" is the cheap, safe "second opinion" they ask for before committing, whereas a "relay" is for the heavy lifting of building an artifact. The "show your seams" philosophy (SKILL.md:92) is the key value proposition for a cross-model feature.

### 2. Spec Quality
**[Pass]** `SKILL.md` is honest about its limitations (repo-local, requires CLIs) and provides a prescriptive, high-signal reconciliation structure (Disagree/Agree/Call).
- **Cite:** `SKILL.md:73-82` provides clear, actionable steps for the coordinator.
- **Cite:** `SKILL.md:92` "Surface disagreement; never average it away" is a critical directive that prevents the skill from falling into "consensus hallucinations."

### 3. Implementation
**[Pass]** The use of `git worktree` for isolation is excellent. It ensures that the advisors see the operator's current WIP (including untracked files) without any risk of clobbering the real working tree.
- **Strength:** `consult.sh:114` captures tracked WIP via `git stash create`, and `consult.sh:124` overlays untracked files via `cp`. This is a robust way to recreate the user's "live" environment for the advisors.
- **Safety:** The `trap cleanup EXIT` (consult.sh:118) ensures the isolation worktree is pruned even on failure.
- **[Should]** `consult.sh:124`: The untracked file copy `cp -p` respects `.gitignore` (via `ls-files`), but could be slow if the user has large untracked assets (e.g., local `.db` or `.log` files not yet ignored). A `max-depth` or size limit check would be a safer commercial default.

### 4. Commercial Readiness
**[Should]** **Cost Visibility.** For a paid product, the "best-effort" cost capture (consult.sh:159) is insufficient.
- **Finding:** Currently, `tick cost` only triggers for Gemini and *only* if `CONSULT_GEMINI_JSON=1` is set. Codex cost capture is explicitly "deferred."
- **Impact:** A paying user running a "consult" is invoking two high-end models simultaneously; they need to know the total token/dollar cost of that "one-shot" action immediately.
