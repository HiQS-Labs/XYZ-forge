**Verdict:** Recommend **command-local sweep reuse + closure-first gating of `read_native_issue` only if the two-observation contract is scoped to closing transitions, OR — when two observations are required for every nonterminal row — bounded per-repo bulk native inventory (`gh api repos/<repo>/issues?state=all&per_page=100` with a strict page cap and per-row `read_native_issue` fallback) paired with command-local sweep reuse across callers.** Between the two options named in the prompt under the strict "preserve two observations on every row" invariant, **command-local sweep reuse is the smallest, lowest-risk source reduction within a multi-step command**, while **bounded bulk native inventory** is the only option that reduces the $N$ native REST reads *inside* a single [`cmd_roadmap_reconcile_state`](utils/py/releases_app.py#L4277-L4372) invocation (e.g., from 90 native REST calls to 1–3 paginated REST calls + fallback), at the cost of pagination/PR-noise and freshness-window trade-offs detailed below.

### 3. Concrete Objections & Failure Modes to Guard Against

1. **Objection to naive bulk REST (`repos/<repo>/issues`): PRs consume pagination and must still trigger hard rejection.**
   - GitHub's `GET /repos/{owner}/{repo}/issues` endpoint returns **both issues and pull requests**. In a repo with hundreds of PRs between nonterminal issue numbers, `state=all&per_page=100` will mostly return PRs, causing low hit rates for older open issues, while `state=open&per_page=100` misses issues that just closed (forcing fallback for every closed issue, which is actually fine since closed nonterminal rows are few).
   - **Trap:** If bulk prefiltering drops items with `"pull_request" in item` before populating the lookup map, a roadmap row that accidentally points to a PR number will look like a "cache miss" and trigger an extra per-row [`read_native_issue`](utils/py/releases_app.py#L5680-L5693) call (or worse, if someone only checks `state=open`, fail to reject a closed PR). Bulk indexing must record `"pull_request" in item` as an explicit invalid entry (or let the per-row fallback reject it identically).

2. **Objection to bulk REST without fallback: breaks existing offline `gh` test shims.**
   - Existing unit/governance tests stub `gh api repos/<owner>/<repo>/issues/<N>` per issue number and do not stub `repos/<owner>/<repo>/issues?state=...`. If a bulk call failure aborts [`cmd_roadmap_reconcile_state`](utils/py/releases_app.py#L4277-L4372), offline test fixtures break immediately. Any bulk inventory **must** degrade gracefully to per-row [`read_native_issue`](utils/py/releases_app.py#L5680-L5693) when the bulk endpoint is unstubbed or returns non-zero/non-list in a test shim, **or** be gated so that per-row fallback is only used when the bulk list is unavailable? Wait: if a live bulk call fails due to a real GitHub outage, falling back to 90 per-row calls will just fail 90 times; only fallback on cache miss (or when bulk is unsupported by a mock shim) makes sense.

3. **Objection to bulk REST freshness skew (`changed from native ... during lookup`).**
   - In [`cmd_roadmap_reconcile_state`](utils/py/releases_app.py#L4321-L4332), `native["state"]` and `issue["state"]` are currently sampled milliseconds apart per row. If `native` comes from a bulk snapshot taken at the start of a 90-row loop and `read_issue_closure_state` runs 20–30 seconds later, any concurrent issue close/reopen during that window will trigger a false `reconcile-state-lookup` refusal.
   - **Mitigation:** If a bulk-sourced `native["state"]` disagrees with `issue["state"].lower()`, call single-row [`read_native_issue(identity["repo"], row["gh_number"], url)`](utils/py/releases_app.py#L5680-L5693) once right then to confirm whether the state is genuinely flapping in flight or merely changed between the bulk prefetch and the row check.

4. **Objection to [`pre_merge_ledger_gate`](skills/2-daily/merge-cleanup/scripts/ledger_merge.py#L658-L687) running full 90-row remote reconciliation per PR.**
   - Look at what [`pre_merge_ledger_gate`](skills/2-daily/merge-cleanup/scripts/ledger_merge.py#L658-L687) checks on each landing clone: `releases check` + `roadmap reconcile-state --dry-run`.
   - When landing $K$ PRs in [`_land_prs_loop`](skills/2-daily/merge-cleanup/scripts/merge_cleanup.py#L1639), if a PR does not modify `releases.sql` / `releases.db` (i.e., `sem["changed_theirs"]` is false in [`ledger_semantic_check`](skills/2-daily/merge-cleanup/scripts/ledger_merge.py#L455-L500)), the set of nonterminal `roadmap_items` rows in the landing clone is identical to `origin/<branch>`. Even when a PR *does* add 1 row to `roadmap_items`, the other 89 rows are unchanged. Re-querying all 90 rows over the network for every PR in a dry-run or landing batch multiplies wire traffic by $K$.

### 4. Smallest Safe Source Recommendation (Post-Measurement)

Once parent workflow measurement confirms whether wire volume is dominated by **(a) single-sweep `reconcile-state` cost ($90 + 90$ calls)** or **(b) repeated sweeps across `merge_cleanup` / `wave_reconcile` ($K \times 180$ calls)**:

1. **Inside [`utils/py/releases_app.py`](utils/py/releases_app.py) (`cmd_roadmap_reconcile_state`):**
   - Implement a **bounded bulk open-issue native prefetch** per qualified repo (`gh api "repos/<repo>/issues?state=open&per_page=100"`, capped at e.g. 1–2 pages) *only* when a repo has $>1$ qualified nonterminal row in the sweep:
     - Validate every non-PR entry in the bulk response with the exact [`read_native_issue`](utils/py/releases_app.py#L5688-L5692) field predicate (`isinstance(item, dict)`, `"pull_request" not in item`, `item.get("number") == number`, `item.get("html_url") == issue_url`, `item.get("state") == "open"`, `isinstance(item.get("labels"), list)`).
     - Because the vast majority of nonterminal roadmap rows are still `open` on GitHub, a single `state=open&per_page=100` call (which excludes closed PRs and only includes open issues + open PRs) satisfies Observation 1 (`native`) for almost all open nonterminal rows in **1 REST call**.
     - For any row **not** found in that bounded `state=open` map (i.e., any issue that has actually **closed**, any row that is a PR, any row beyond page 1, or if the bulk call fails in an offline single-issue test shim), fall back to the existing per-row [`read_native_issue(identity["repo"], row["gh_number"], url)`](utils/py/releases_app.py#L5680-L5693).
     - If a row had `native["state"] == "open"` from the bulk prefetch but [`read_issue_closure_state`](utils/py/releases_app.py#L4263-L4274) returns `CLOSED` (because the issue closed during the sweep), re-run single-row [`read_native_issue`](utils/py/releases_app.py#L5680-L5693) once before deciding whether to refuse with `changed from native open to closed during lookup`.
   - **Why this is the smallest safe change:**
     - Every row still gets **two independent observations** (REST + `gh issue view`).
     - Every closed/transitioning row and every PR row still hits the exact per-row [`read_native_issue`](utils/py/releases_app.py#L5680-L5693) verification path before any DB write or refusal.
     - Existing offline test shims that only stub `repos/<repo>/issues/<n>` continue to work unchanged via the fallback.
     - [`perform_write`](utils/py/releases_app.py#L4350-L4364) transactional concurrency (`BEGIN IMMEDIATE` + full row equality check) is completely unchanged.

2. **Across [`utils/py/wave_reconcile.py`](utils/py/wave_reconcile.py) / [`skills/2-daily/merge-cleanup/scripts/ledger_merge.py`](skills/2-daily/merge-cleanup/scripts/ledger_merge.py) (Command-Local Sweep Reuse):**
   - In [`wave_reconcile.py`](utils/py/wave_reconcile.py#L964-L995), memoize [`read_issue_closure_state(root, issue_url)`](utils/py/releases_app.py#L4263-L4274) by `issue_url` within a single `wave_reconcile` process so `_sweep_issue_docs` and delivery checks do not re-fetch the same `issue_url`.
   - Do **not** share a mutable cross-PR cache across `execute_pr_merge` boundaries in [`_land_prs_loop`](skills/2-daily/merge-cleanup/scripts/merge_cleanup.py#L1719), because merging PR $i$ closes linked issues on GitHub and invalidates prior `OPEN` observations for PR $i+1$.
